# quote-check · 견적 앱 변경 후 점검

앱을 고친 뒤 사람이 `/quote-check`로 부른다. 아래 네 단계를 순서대로 돌린다.

## 지킬 것

- **실행하지 않은 항목을 통과로 쓰지 않는다.** 돌려서 맞으면 통과, 돌려서 틀리면 실패, 못 돌렸으면 **미검증**이다.
- API 키를 읽거나 출력하지 않는다. `.env` 내용을 열지 않는다. 파일이 있는지 이름만 확인한다.
- **실제 발송·예약 확정·배포는 이 Skill의 범위 밖이다.** 하지 않는다.
- 금액은 화면에 나온 값을 그대로 읽는다. 직접 계산해서 채워 넣지 않는다.

---

## 1단계 · 데이터 출처 확인

`public/data/rates.json`과 `public/data/sources.json`을 읽고 확인한다.

- 요율 줄마다 `currency` · `basis` · `effectiveFrom` · `effectiveTo` · `provenance` · `sourceId`가 있는가
- `sourceId`가 `sources.json`에 실제로 있는가
- `provenance: estimate`인 줄에 `assumption`(교육용 가정 설명)이 적혀 있는가
- `public/data`가 원본 `data/`와 어긋나지 않는가

결과: 통과 / 실패 / 미검증

## 2단계 · 자동 테스트

```bash
npm test
```

- **통과·실패 개수를 그대로 보고한다.** 실패가 있으면 어떤 테스트가 왜 실패했는지 적는다.
- 실패를 통과로 바꿔 쓰지 않는다.

## 3단계 · Playwright MCP로 4사례 화면 확인

먼저 앱 주소를 확인한다. 모르면 `README.md`와 실행 중인 서버를 확인하고, 그래도 없으면 사람에게 묻는다.

**MCP가 연결되지 않았으면 이 단계 전체를 `미검증`으로 보고하고 아래 복구 안내를 낸다.**

> **MCP 복구 안내**
> 1. Claude Code에서 `/mcp`를 넣어 `playwright`가 `Connected`인지 본다. (`Added`는 아직 연결 전이다)
> 2. `Connected`가 아니면 `/exit`로 나간 뒤, 터미널에서 같은 폴더에 `claude --continue`를 넣어 다시 연다.
> 3. 다시 열 때 이 프로젝트의 MCP를 쓸지 묻는 창에서 `playwright`를 승인한다.
> 4. 이 프로젝트의 `.mcp.json`에 등록된 명령은 다음과 같다:
>    `npx -y @playwright/mcp@0.0.82`
> 5. `/exit`로 나오면 앱 서버도 함께 꺼진다. 다시 켜 달라고 부탁한 뒤 새 주소로 검사한다.

스냅샷을 읽고 **실제 입력·선택·클릭 도구로** 값을 넣는다. 각 사례마다 기대값과 실제값을 나란히 적는다.

### ① 정상 — 20GP 2대 · B/L 1건 · KRPUS→VNHPH · 준비 2026-09-22 · 출항 2026-09-25 · 비위험물 · CY-CY

- 기대: USD **1,280** · KRW **340,290** · VND **950,000**
- 기대: 보류 항목 없음
- 기대: 컨테이너당 줄은 수량을, B/L당 줄은 B/L 건수를 곱함

### ①-2 수량 2 → 3 (컨테이너당만 증가)

- 기대: USD **1,920** · KRW **490,435** · VND **950,000**
- 기대: B/L당 비용은 그대로 (40,000 KRW · 950,000 VND)

### ② 수량 누락

- 기대: 수량 칸이 **빈 값으로 남는다**. 1이나 0으로 채우지 않는다
- 기대: 컨테이너당 요율이 **금액 없이 보류**되고 사유에 수량 확인이 적힌다

### ③ HC 요율 없음 — 40HC

- 기대: 금액이 하나도 나오지 않는다
- 기대: 보류 사유에 **GP 요율을 대신 적용할 수 없다**는 내용이 있다

### ④ 적용기간 밖 — 출항 2026-10-08

- 기대: 3분기 LSF가 **적용기간 밖으로 보류**된다
- 기대: USD가 **부분 소계 880**으로 표시된다
- 기대: KRW 340,290 · VND 950,000은 그대로

### 화면 크기

- **390px**와 **768px**로 줄여 가로 스크롤 없이 금액이 다 보이는지 확인한다
- 버튼·입력의 최소 높이 44px이 지켜지는지 확인한다

## 4단계 · evidence 기록

`evidence/` 폴더에 이번 점검 기록을 남긴다.

- 사례마다 **기대값 · 실제값 · 통과/실패/미검증**을 나란히 적는다
- 캡처를 남긴다 (같은 문의 · 같은 창 크기)
- 실패가 있으면 원인과 고친 내용을 적는다
- 실행하지 못한 항목은 **미검증**으로 남기고 왜 못 했는지 적는다
